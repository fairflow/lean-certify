# Lean certify v0.2.1: R3 on theorems (statements, tests, results)

2026-10-14, branch `r3-decided-theorems`. A behaviour fix to a lint, asked
for by Matthew: termination arguments are what most need the certified
route, and R3 did not check them where they matter most.

## The gap

R3 ("termination arguments stay in the theory and are never recomputed at
run time") is enforced by `#certify_structural`, which walks a
*definition's* value. On a theorem there was no value to walk, and the
command still printed "R3 passes". So a theorem proved by `decide` or
`decide +kernel` whose decision procedure reaches `WellFounded.Nat.fix` was
never flagged. Observed on v0.2.0:

```
theorem halvings_8 : halvings 8 = 3 := by decide +kernel
#certify_structural halvings_8
-- R3 passes: the evaluation path of halvings_8 is structural
```

## Statements

- **S3.** `#certify_structural` and `#certify_domain` on a theorem never
  pass vacuously: they walk what its proof decides by evaluation (S2), or
  report an error naming the theorem and saying there is nothing to walk.
- **S2.** What a proof decides by evaluation: each application of
  `of_decide_eq_true`, `of_decide_eq_false`, `eq_true_of_decide` or
  `eq_false_of_decide` (the proposition `p`, its `Decidable p` instance, an
  equation `decide p = b`) whose equation is proved by reflexivity
  (`Eq.refl` or `rfl`, under `id`), in the theorem's proof or in an
  auxiliary theorem generated for it (same module, implementation-detail
  name: `t._proof_1_1` from `decide +kernel`, `_auxLemma`, `proof_1`). The
  R3 walk starts from the definitions in `p` and the instance, enters
  definitions and never theorems, and reports every constant R3 forbids,
  with the chain of constants from the theorem. A `Certifier` or `Engine`
  among them is walked through its `check` functions only, as when it is
  the root, so a fact `K.verdict s c` is not blamed for an untrusted
  `partial` producer.
- **Severity (decision D2).** What R3 forbids on a theorem is an error.
  Chosen by the project's manager on Matthew's statement; it is one line to
  flip to a warning (`Certify.Lint.decidedOffenceIsError`).
- **Allowance.** `#certify_structural f allow c "reason", …` names a
  constant `c` on the evaluation path and the reason. What R3 forbids at or
  below `c` becomes a warning (the walk stops at `c`; `c` is walked on its
  own); everything else keeps its severity. An allowance not on the path,
  or one below which R3 forbids nothing, is an error. It works the same on
  a definition.
- **`@[implemented_by]` under the kernel route.** Unchanged: the
  constant itself is a note, not an error (decision (b)). New: the walk
  now *enters* it, since its value is what the kernel reduces. v0.2.0
  stopped there, so whatever lay below was never checked: core
  `Array.contains` reaches `Array.anyM` (`@[implemented_by]`), whose value
  loops by `WellFounded.Nat.fix` through `Array.anyM.loop`. Under any other
  route it is still an error and not entered.

Not changed: R3 never enters a theorem; a proof by `rfl` (or any kernel
reduction other than the four lemmas above) is not walked, and so reports
"nothing to walk". `#certify_structural` on an axiom, an opaque constant or
an inductive still passes vacuously, as before (outside this fix).

## Acceptance tests (`LeanCertifyTest/Decided.lean`)

All 15 `#guard_msgs` were watched failing against v0.2.0 (each printed
"R3 passes: the evaluation path of … is structural", "R1: nothing to
report on …", or failed to parse the `allow` clause), and pass after:

1. `halvings_8`, decided through a `termination_by` function: an error,
   via `[halvings_8, halvings, WellFounded.Nat.fix]`.
2. Core at v4.31.0 has no `Nat.sqrt`; `#[1, 2, 3].contains 2 = true` by
   `decide +kernel` is an error, via `[has_two, Array.contains, Array.any,
   Array.anyM, Array.anyM.loop, WellFounded.Nat.fix]`, with the
   `Array.anyM` note; and the same on a definition (`checkHas`), which
   v0.2.0 passed with the note alone.
3. Structural only (`sum_4` by `decide`, `sum_5` by `decide +kernel`, a
   certifier fact `sq_64` whose engine has a `partial` producer): passes
   and prints the propositions walked; R1 likewise.
4. No decided content (`add_zero'`; `root_ok`, which applies
   `of_decide_eq_true` to a hypothesis): "cannot check … nothing to walk",
   for R3 and R1.
5. `both : halvings 8 = 3 ∧ steps 2 = 2` with `allow halvings "…"`: the
   error via `steps` stays, the one via `halvings` becomes a warning; an
   allowance off the path, or with nothing forbidden below it, is an error;
   the same on a definition.
6. The whole existing suite, unchanged, on v4.31.0 and v4.33.0.

## Release

0.2.1, a patch release: no signature of the interface (`Certifier`,
`Verdict`, `Engine`, `Refinement`, `Config`, `CertifierConfig`,
`@[harness]`) changes; `allow` is a non-reserved keyword, so an identifier
named `allow` still parses. The lint is stricter, so see the README's
migration note.
