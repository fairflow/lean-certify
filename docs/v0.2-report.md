## Demonstrations (locus, branch `certify-v2`, local, ce006b3)

Agreed with the logic lane, who asked for the generator to be changed rather
than its output, and for the two savings to be measured separately.

**A on ABP.** The generator `ABPGen.lean` now emits the field-wise checks
(`tstateOkB`, `bdEqB`) and streams the graph check over two files of 7 chunks
each, assembled by `certify_all`. The certificate is byte-identical to
before, `abp_wbisim_buff`'s statement is unchanged, its pins stay at
`[propext, Quot.sound]`, and a corrupted row is watched rejected.

| | before | after |
|---|---|---|
| per chunk (8 states), kernel | 5.7–47.3 s, ≤ 7.49 GB | 2.2–3.1 s, ≤ 2.62 GB |
| all 14 chunks, kernel | 311.8 s | 37.0 s |
| whole example | ~5 min, 9.5 GB, one process | 42 s in sequence, ~25 s in parallel; max 3.15 GB per process |

Almost all of the saving (8.4× in kernel time) is the field-wise state
equality replacing the derived `DecidableEq`. Chunking and streaming do not
change the cost of a chunk: they keep each process within the 4 GB / 30 s
budget (before, 7 of 14 chunks exceeded 4 GB), let the files build in
parallel, and replace the hand-written 14-case assembly.

**B on M1′ (fits).** `Logic/Examples/M1Prime/ToyFast.lean` is new: it
packages `m1Prime_refines` as a `Refinement` on the toy, and
`certify_fastpath m1Toy` gives one definition that the kernel reads as
`checkC` and compiled code runs as `checkG`. The shape (c) fits exactly:
`fastEval` reads the specification, and `dom` is `i < c.ss.length`. Limit,
stated in the file at the logic lane's request: kernel evaluation of
`checkC` is the slow search route, so the kernel side is for toy-sized
systems only.
