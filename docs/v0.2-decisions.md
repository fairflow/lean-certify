## (b) R3 and `@[implemented_by]` under the kernel route

Under `route := .kernel`, an `@[implemented_by]` declaration on a checker's
evaluation path is reported as **information, not an error**. The kernel
always reduces the reference definition and never runs the replacement code,
so the clause matters only to compiled checking (`route := .native`).
`WellFounded.fix`, `WellFounded.Nat.fix`, `._unary`/`._binary` auxiliaries
and opaque constants remain errors.

Evidence: locus's `wbisimCertifier` is flagged because `Match.guard` builds
error strings (`throw s!"redex node {v} …"`), which reach `Nat.repr`
(`@[implemented_by]`). The toy certificates nevertheless check in the
kernel, in about 125–145 ms each (`Logic/Certify.lean`, locus f3117a9). An
exemption for error-message builders was rejected: unlike a panic message,
an `Except` error string can be inspected, so such an exemption would not be
sound in general.

## (c) The shape of `Refinement`

```lean
structure Refinement (Spec Cert Q : Type) (specEval : Spec → Q → Bool) where
  valid    : Spec → Cert → Bool
  dom      : Spec → Cert → Q → Bool
  fastEval : Spec → Cert → Q → Bool
  refine   : ∀ s c q, valid s c = true → dom s c q = true →
               fastEval s c q = specEval s q
```

Changed from v0.1 in two places. `fastEval` now takes the specification:
M1′'s fast evaluator `checkG` needs the signature and atoms, which are
specification data. And the new domain `dom` limits where the equation must
hold: `m1Prime`'s refinement holds only at listed indices
(`i < c.ss.length`). With `Spec := (S, rules, atoms, ss)` and
`valid := g1 && certCheck && c.ss = ss && the eqUpTo-closure as a Boolean`,
`M1PrimeRefinesStatement` then fits unchanged.

This changes an interface signature, so it belongs in a minor release
(v0.2), with a migration note (README, "Versioning").
